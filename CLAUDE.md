# gloomy-cpp

C++23 respin of gloomy (`~/prsn/gloomy`, Rust/wgpu, ~18k lines: SDF primitives, flexbox/grid layout, themes, RON-declared UIs, rich text, virtualised DataGrid, charts, designer). Renders on raw Vulkan; windows and input through SDL2 (Vulkan surface) for now. First consumer: the X-conomy client (`~/dev/x_conomy`), which needs very large searchable tables and long searchable text (contracts).

Design: `docs/design.md` (read it first; section 2 is the guiding principle "deep data, accessible surface"). gloomy is a reference for the low level only, not for the widget layer.

Current state: all five phases done; see docs/design.md section 17 for what is built and what is not (docking, column groups, tree rows, document text selection, trigram index, bidi). Apps: `gloomy_demo` (widget gallery), `gloomy_showcase` (X-conomy market screen over 1M rows, contract, overview panels, Ctrl+K/Ctrl+P finder), `gloomy_bench` (frame times, docs/design.md section 14.1).

## Build and test

```bash
cmake -B build-debug -DCMAKE_BUILD_TYPE=Debug -G Ninja
cmake --build build-debug -j4 && ctest --test-dir build-debug -j4
# Headless screenshot of the demo (any Vulkan device, lavapipe shown):
VK_ICD_FILENAMES=/usr/share/vulkan/icd.d/lvp_icd.json \
    ./build-debug/src/apps/demo/gloomy_demo --screenshot /tmp/demo.png
# Release build, showcase screenshots (--tab 0..2, --finder "query"), bench:
cmake -B build-release -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTS=OFF -G Ninja
cmake --build build-release -j4
./build-release/src/apps/showcase/gloomy_showcase --tab 2 --screenshot /tmp/s.png
./build-release/src/apps/bench/gloomy_bench   # GPU; VK_ICD_FILENAMES for lavapipe
```

- GPU tests run on lavapipe: ctest sets `VK_ICD_FILENAMES` from the cache variable `GL_TEST_ICD` (`tests/CMakeLists.txt`); empty means the system default device.
- Validation (`VK_LAYER_KHRONOS_validation`) is on in every GPU test; any message fails the test (`tests/test_support/gpu_test.cc`). `GLOOMY_NO_VALIDATION=1` turns it off.
- Image tests compare with `tests/reference/*.png` (tolerance per channel, max differing pixels). On failure `build-debug/test_output/<name>_actual.png` and `_diff.png` are written. `GLOOMY_UPDATE_REFERENCES=1 ctest ...` rewrites references: always look at the new images (Read tool) before committing them, and run `clang-format -i` and rebuild first (reordered includes can pick other float/double overloads and shift pixels slightly). Make sure the build succeeded; ninja stops at the first error and leaves stale test binaries.
- `GLOOMY_DEVICE=<index>` picks a physical device.
- Dependencies (system): Vulkan headers/loader, glslc, FreeType, HarfBuzz (pkg-config), libpng, SDL2 (`-DBUILD_PLATFORM_SDL2=OFF` to skip), GoogleTest (system or fetched); nanosvg is fetched (`GLOOMY_NANOSVG_DIR` for offline builds).

## Layout

Like X-conomy: public headers `include/gloomy/<module>/`, implementation `src/gloomy/<module>/`, each module an OBJECT library in `cmake/BuildGloomyLib.cmake`, collected into the static library `gloomy`; SDL2 platform layer is the separate `gloomy_sdl2`. Tests `tests/<module>/test_<name>.cc`, registered by `tests/cmake/<module>/test_<name>.cmake`. Apps in `src/apps/`.

- Shaders: `src/gloomy/gfx/shaders/ui.{vert,frag}`, compiled by glslc at build time and embedded (`cmake/CompileShaders.cmake`, `cmake/EmbedFileScript.cmake`). Fonts in `assets/fonts/` (Liberation, OFL) are embedded the same way (`cmake/EmbedFiles.cmake`).
- One instance format for every primitive: `Instance` in `include/gloomy/gfx/draw_list.h`; must match the vertex attributes in `src/gloomy/gfx/ui_renderer.cc` (`CreatePipeline`) and `ui.vert`.
- Device ownership vs. UI rendering: `gfx::DeviceContext` (`Create` or `Wrap` a host device), `gfx::UiRenderer` (`Prepare` outside, `Draw` inside the caller's dynamic rendering), `gfx::OffscreenTarget`, `gfx::Swapchain`.
- UI frame model: `ui::Context` (`include/gloomy/ui/context.h`): immediate-mode declaration into a per-frame node tree; input resolves against the previous frame's layout (`ProcessEvents`, `HitTest`); results are swapped in at the end of `EndFrame()`; per-id state via `State<T>(id)`; overlay layers (`BeginLayer`: popup, tooltip, modal). Layout engine: `ui::LayoutTree` (`src/gloomy/ui/layout.cc`, Clay-style passes). Widgets: `include/gloomy/ui/widgets.h`. Themes: `src/gloomy/ui/theme.cc` (`Theme::Scaled()` multiplies every metric: a UI scale setting, `ctx.SetTheme(base.Scaled(f))`).
- Data layer (`include/gloomy/data/`): `TableSource` (typed access, `Explain`), `ColumnarTable`, `FunctionTable` (zero-copy adapter for SoA), `Query`/`Execute` (`src/gloomy/data/query.cc`: filters, parallel multi-key sort, narrowing/resort/cache paths), `SearchCorpus` (`src/gloomy/data/search.cc`), `TableView` (`src/gloomy/data/table_view.cc`: sync below 50k rows, else worker thread with cancellation), `Document` (Markdown subset, `src/gloomy/data/document.cc`).
- Charts: `ui::LineChart` (`src/gloomy/ui/chart.cc`; NaN y values are gaps, lone points between gaps are dots, `ChartOptions::x_format` formats time axes). Timelines (events on a time axis, past solid and future dashed, expected events as rings, deadlines as bars; for messages in transit): `ui::Timeline`, pure label layout `LayoutTimeline()` (`src/gloomy/ui/timeline.cc`). Custom-draw canvas with pan/zoom camera and picking (for game maps): `ui::Canvas`, `CanvasState`, `PickNearest()`, `PickAll()`, click cycling `PickCycle`, selection and hover marks `DrawTargetBrackets()` (animated corner brackets) and `DrawHoverRing()` (`src/gloomy/ui/canvas.cc`); arrows/Enter come from the app's `NavigationTarget` via `Navigate()`. Label decluttering for maps: `ui::LabelPlacer` (`src/gloomy/ui/label_placer.cc`: requests with priority, abbreviation, preferred side, forced labels; obstacles; pure geometry `Place()` testable without a GPU, `Draw()` paints). Docking: `ui::DockLayout`, `ui::DockSpace` (`src/gloomy/ui/dock.cc`).
- Answer-first widgets (design section 2): `include/gloomy/ui/summary.h` (ExplainedLabel, Sparkline, SummaryCard, SummaryPanel, AnswerLine), `include/gloomy/ui/view_preset.h` (presets, encode/decode, PresetBar), `include/gloomy/ui/navigation.h` (NavigationTarget, Navigate, NavigationProvider). Finder (palette + global search): `src/gloomy/ui/finder.cc`. Menus (context menus, `BeginMenuButton` "More" menus, items with hints), dialogs (nested, `DialogOptions` summary line), toasts, split panes: `src/gloomy/ui/overlays.cc`. Detail views (progressive disclosure: card, key facts, chip, big button, segmented control, `TabMemory`/`RememberedTabs`, section header, form row, empty state): `src/gloomy/ui/disclosure.cc`; `PresetSegments` (presets as segments with counts) in `src/gloomy/ui/view_preset.cc`; tests `tests/ui/test_disclosure.cc`, image `disclosure_dark`. Hub tiles (one-line answer, the items behind it, one action; a grid whose columns follow its width): `src/gloomy/ui/dashboard.cc`, tests `tests/ui/test_dashboard.cc`. Menu list for game menus (keyboard-first, detail lines, disabled items say why): `src/gloomy/ui/menu_list.cc`. Key chords for rebindable keys (names, parse, consume, capture button, `SwallowKeys()`): `src/gloomy/ui/key_chord.cc`. Radial context menu (options round the pointer, right-drag-release, keys, disabled options say why): `src/gloomy/ui/radial_menu.cc`, overlay layer `LayerKind::kOverlay`.
- Grouping: `Query::group_by`/`aggregates`, `BuildGroups` (`src/gloomy/data/query.cc`), `DisplayRows` (`src/gloomy/data/display_rows.cc`); the grid works on display lines (`LineRow`, `LineKey` in `src/gloomy/ui/data_grid.cc`). Append-only sources: `ExecuteAppend`.
- Data widgets: `ui::DataGrid` (`src/gloomy/ui/data_grid.cc`; selected rows get a bar in `Palette::selection_accent` when its alpha is above 0: `HandleKeys`, `HandlePointer`, `PaintGrid`, `HeaderMenu`; a cell hit right of the last column has `Hit::col` -1: never index `state.columns` with it), `ui::DocumentView` (`src/gloomy/ui/document_view.cc`, Fenwick tree over block heights), `ui::SearchField` (`src/gloomy/ui/widgets.cc`). Rich text layout: `text::LayoutRich` (`src/gloomy/text/rich_layout.cc`).
- Headless UI tests drive a `testing::UiHarness` (`tests/test_support/ui_harness.h`) with synthetic events; no GPU needed. SDL event translation: `platform::TranslateEvent` (`src/gloomy/platform/sdl_window.cc`).
- App shell (`include/gloomy/app/app_shell.h`, target `gloomy::app`): `RunApp()` runs a UI function in an SDL2 window or headless into a PNG (`--screenshot`, `--size`, `--frames`); `FrameInfo` carries time and dt (1/60 s per frame headless, so screenshots are deterministic); `headless_input` scripts input per frame, `ParseKeyList()` parses "Down,Enter,Ctrl+K" ("Release+W" releases a held key). In a window, `--quit-after-frames N` (`ShellOptions::quit_after_frames`) posts a quit event as closing the window does (`SdlWindow::PostQuit()`), to test exit paths.
- Held keys for continuous control (games): `Context::IsKeyDown()`, `ReleaseKeys()`; `ConsumeKey()` sees presses only.
- As a subproject (`add_subdirectory` or FetchContent, as X-conomy's `xc_client` does) only the libraries build: `BUILD_APPS`/`BUILD_TESTS` are forced off, and `cmake/` is prepended to `CMAKE_MODULE_PATH` so the parent's modules of the same name do not shadow ours.
- Icons (`include/gloomy/icon/`, module `GlIcon`): `icon::IconSet` parses SVG with nanosvg (fetched at a pinned commit in `cmake/ProjectDependencies.cmake`, or `-DGLOOMY_NANOSVG_DIR=` for a local checkout) and rasterises coverage masks at exact pixel sizes (`Rasterise()`, subpixel shifts, rotation; `Dilate()` for halos); icons are masks, tinted when drawn, so one icon serves every colour. `icon::IconCache` puts them into the text atlas (both caches start over when either clears it, via `Atlas::generation()`) and draws them (`Draw()`, `DrawInRect()`, `IconDrawOptions`: halo, exact (bilinear) placement for moving objects, rotation in `kIconRotationSteps`). The `ui::Context` owns one set and cache: register with `ctx.icons().Add(name, svg)`, draw with `ui::Icon()`, `PaintContext::icons` in painters and canvases, or in grid cells via `TableSource::GetIcon()` (`CellIcon`, drawn in front of the text by `DataGrid`). Tests `tests/icon/` (reference `tests/reference/icons.png`).
- Text: `text::FontSet` (faces, fallback chains), `text::Shaper` (HarfBuzz, font fallback runs, clusters = byte offsets), `text::GlyphCache` (FreeType coverage bitmaps, 4 subpixel bins, into `core::Atlas`), `text::TextSystem` (shape cache, wrap, draw).

## Conventions

Same as X-conomy / OTC.SDK branch `staging-v12`: Google C++ style, C++23, `snake_case.h/.cc`, include guards (no `#pragma once`), trailing return types, PascalCase functions, `member_` suffix, `kConstants`, `///` doxygen comments on the line above, `.clang-format`/`.clang-tidy`/`.editorconfig` in the repo (`clang-format -i` before committing). Python follows `.flake8`. Unit tests (GoogleTest) for all code; one test file per test binary. Markdown prose is never hard-wrapped.
